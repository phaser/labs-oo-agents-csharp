# Porting notes

One entry per deliberate deviation from upstream. Upstream pin: see [`port-plan.md`](port-plan.md).

Format: `## <upstream concept>` → **C#:** what we do. **Why:** reason. **Tests:** upstream tests skipped or changed.

## `...` method bodies

**C#:** `[Agentic] public partial Task<T> M(...);`. The source generator emits the body.
**Why:** C# has no `...` body. A partial method with no body is a compile error, so the generator is mandatory.
**Tests:** `test_ellipsis_detection_exec.py` and the bytecode fallback tests do not apply.

## Pre-ellipsis code

**C#:** Not supported in v1. Upstream runs statements before the `...` first.
**Why:** a partial declaration has no body. A later option is an `OnBefore<Method>` partial hook.
**Tests:** `test_pre_ellipsis_code.py` is deferred.

## Docstrings as prompts

**C#:** XML doc comments. The generator embeds `<summary>` (and `<remarks>`) as string constants.
**Why:** doc comments are not in the compiled assembly.

## REPL action language

**C#**, through Roslyn scripting. Upstream uses Python `exec`.
**Why:** decision D1 in the plan. All prompts and error hints are rewritten for C#.

## Dynamic method guard

**C#:** Not ported. `__setattr__` guards are not needed in a static language.
**Tests:** `test_dynamic_method_guard.py` does not apply.

## Config records (pydantic `model_fields_set`)

**C#:** `ConfigBase` (a record) keeps the set of explicitly set property names. Each property is
`{ get; init { field = value; MarkSet(); } } = default;` (C# 14 `field` keyword). A property initializer writes the backing field
directly, so a default is not "set". `MergeWith` copies only the set properties of `other`, and an explicit `null` counts as set.
`with` copies get their own set. The tracking set does not take part in value equality.
**Why:** pydantic merge semantics. Frozen models become immutable records (`init` only).
**Tests:** `ConfigBaseTests` verify the tracking. Upstream `test_*_frozen` tests are replaced by an init-only check. `model_construct`/`model_validate` tests do not apply.
**Message:** the "no fields set" error is an `ArgumentException`. The text is adapted: it does not mention `model_dump()`/`model_validate()`.

## Config validation

**C#:** Validation is explicit: `config.Validate()` throws `ConfigValidationException` with the upstream multi-line format
(`Invalid CaptureConfig:\n  - ...`). `TruncationConfig.Validate()` validates its sub-configs first. Bullets use C# property names.
**Why:** pydantic validates in the constructor. A C# object initializer runs after the constructor, so construction cannot validate.
`MergeWith` does not re-validate (upstream `model_copy` does not either). Callers validate the final config.

## Layered config, `llm_config.py`, `paths.py`

**C#:** `Nooa.LayeredConfig`, `Nooa.LlmConfig`, `Nooa.Secrets`, `Nooa.NooaPaths` (static classes, root namespace). YamlDotNet parses YAML.

## Untrusted config files (security deviations)

**C#:** Two protections that upstream does not have. A project-layer `.nooa/` directory can come from a cloned repository, so its files are untrusted.
- `Secrets.LoadSecretsIntoEnv` is layer-aware. Every layer: the name must match `^[A-Za-z_][A-Za-z0-9_]*$` and must not be in `SecretEnvDenylist` (one place; defence in depth): `LD_*`, `DYLD_*`, `DOTNET_*`, `COMPlus_*`, `NEMO_OO_*`, `NOOA_*`, `XDG_*`, `GIT_*`, `SSH_*`, `NPM_CONFIG_*`, `PIP_*`, `PATH`, `BASH_ENV`, `EDITOR`, `VISUAL`, `PAGER`, `ZDOTDIR`, `NODE_PATH`, shell and runtime option variables, CA-bundle variables, and the suffixes `*_PROXY`, `*_BASE_URL`, `*_API_BASE`, `*_API_URL`, `*_ENDPOINT`, `*_HOST`, `*_URL`. Project layer (`.nooa/secrets.yaml`, or any file inside the project directory or root, including one named by `NEMO_OO_SECRETS`): only credential-shaped names are accepted (`*_API_KEY`, `*_KEY`, `*_TOKEN`, `*_SECRET`, `*_PASSWORD`, case-insensitive). Trust fails closed: a file is trusted only when it is the user-layer file or a `NEMO_OO_SECRETS` path outside the project; paths compare case-insensitively on macOS and Windows (`NooaPaths.PathComparison`). An untrusted file cannot replace or delete a name that a trusted layer set, and cannot delete any name — **upstream lets the project layer override the user layer; the port does not**, because a project file could swap in an attacker-owned API key and receive the prompts. A refused project value never replaces a trusted one. A warning names the variable, never the value. The "never override an existing variable" rule stays. `WriteSecretEnv` refuses denylisted names.
- `LayeredConfig.ParseYaml` rejects YAML anchors and aliases (alias expansion can build a huge object graph) and nesting deeper than 64 levels. The check scans parser events before deserializing. `LoadLayeredYaml` skips the file with a warning that names the file, as for any bad layer. Direct callers get `InvalidDataException`.
**Why:** an attacker file could set `OPENAI_BASE_URL` and send an existing API key to another host, or load code through `LD_PRELOAD`. A YAML alias bomb could exhaust memory.
**Tests:** new tests in `SecretsTests` and `LayeredConfigTests`. Open item: project-layer `api_base` / `api_key_env` in `llm_config.yaml` can redirect a key too (closed in T10, see below).

## `doc()` rendering (agentdoc, T05)

**C#:** `AgentDocs.Doc(obj | objs, concise, inlineDepth, provider)` in `Nooa.Agentdoc`. The object is a `Type`, a `MethodInfo` or an instance.
Output is C# declaration text. A type shows `///` summary lines, a header (`class`, `record`, `struct`, `enum`, `interface`, `static class`, `abstract class`, and ` : Base` for a custom base type),
then fields and properties, a blank line, and methods. Fields and properties are public instance members, base type first.
Methods are public (instance and `static`), derived type first. Members of `System` base types are left out.
`Description` text shows as a `// text` comment after a field. With no description, the first line of the field type summary is used.
A method shows its summary, then `Args:` and `Returns:` lines (from parameter and return descriptions), then the signature.
Referenced types follow under `## Referenced Types`, in concise form, sorted by name, each type once (`inlineDepth` levels, default 1).
A standalone method shows its type name (`Warehouse.CanFulfillOrder`). Instance values are shown for fields and auto-properties. Computed properties are never evaluated.

```
/// Checks stock.
class Warehouse
{
    int Count = 7;  // Items in stock
    string Name { get; set; } = "East";

    /// Check if the order can be filled.
    /// Args:
    ///   budget: Maximum price
    Task<OrderResult> CanFulfillOrder(List<string> items, double budget);
    static Warehouse Create(int size = 5, string? label = null);
}

## Referenced Types

class OrderResult
{
    bool Ok;
}
```

**Why:** the prompt shows C# to a model that writes C#. Nullable annotations come from `NullabilityInfoContext`. Unconstrained type parameters never get `?` (reflection reports them as nullable).
**Deviations:**
- Source order: reflection has none. `MetadataToken` order approximates it within one type. Fields come before properties. Members of partial types in several files can order differently.
- Hidden members: `[Hidden]` (root namespace `Nooa`) replaces `hidden` and `spec(hidden=True)`. `_`-prefixed and non-public members are excluded. There is no `spec(hidden=False)` opt-in, so the upstream "child unhides parent field" tests do not apply.
- Defaults: upstream shows source defaults of fields. Reflection cannot read field initializers, so a type shows no field defaults. An instance shows its current values. Parameter defaults show.
- Descriptions: `[Description]` replaces `Annotated[T, "desc"]` and `spec(description=...)`. Doc comment text comes from `IAgentDocProvider` (see T11).
- Value text: `PFormat` prints values (T06). Doc limits: field values 3/50/1, parameter defaults 5/50/1 (`max_length`/`max_string`/`max_depth`), non-custom top-level object depth 3, as upstream.
- Not ported: `spec(expand=False)`, `spec.define_doc` and the registry, `DocConfig`, `methods()`, `variables()`, module docs, adapters, protocols, extra runtime attributes (C# types have fixed members).
**Tests:** ported in `AgentDocsTests`, `MemberReaderTests`, `ReferencedTypesTests`, `DocFormatterTests`. The rest are listed in `work/t06-agentdoc-pformat.md`.

## Storage (`runtime/event_backend.py`, `storage/`, T07)

**C#:** `Nooa.Runtime`: `IEventBackend`, `InMemoryEventBackend`. `Nooa.Storage`: `IStorageManager`, `InMemoryStorageManager`, `SqliteStorageManager`, `SqliteEventBackend`, `SqliteJournalMode`, `SnapshotInfo`. `Nooa.Errors`: `SessionAlreadyActiveException`, `CorruptDatabaseException`. The SQLite DDL is the upstream DDL (`events`, `active_tags`, `snapshots`, `schema_version`, same indexes). Package: `Microsoft.Data.Sqlite` 10.0.12 (MIT).
- **Update:** `IEventBackend.Update(tag, Action<EventBase>)` replaces `update(tag, **fields)`. Events are records with init-only properties. The caller sets the mutable members (`Status`, `Tag`, `Metadata`, `ToolCallEvent.Result`). The SQLite backend deserializes, runs the delegate, and saves the event with its `status` column. The in-memory backend changes the live object.
- **Persistence (D11):** events serialize only through `EventBase` with `NooaJson.Options`. The restore allowlist is the `[JsonDerivedType]` list (`EventTypeAllowlist`). No `register_event_type`: a custom event type needs a line in the list. Upstream falls back to a generic `Metadata` event for an unknown `event_type`. The port throws `DeserializationException` that names the type. Corrupt JSON, a non-object root, a missing `event_type` and a bad field are skipped with a warning, as upstream does. The legacy `LLMOutput` to `LLMResponse` migration is not ported (no C# sessions exist).
- **Snapshots:** `IStorageManager` has the blob API only: `SaveSnapshotJson`, `LoadSnapshotJson`, `GetLatestSnapshotId`, `ListSnapshots`. A snapshot is a JSON object text. `AgentSnapshot`, `serialize`/`deserialize`, `markers.py`, `json_snapshot.py`, `save_snapshot(agent)`, `restore_snapshot` and `restore_latest_snapshot` walk agent fields and move to T12. `persistent_vars.py` and `snapshot_vars.py` move to T15.
- **Untrusted files (security deviation):** a session file can come from another machine or a cloned repository. Upstream says the database must be trusted because its restore runs `exec()`. The port has no code execution on restore, and adds: the schema version is checked when the file opens, before any event is read (`InvalidDataException` on a mismatch); each stored event and snapshot has a size limit, and the database has a count and a total size limit (`StorageLimits`, one place: 64 MiB per row, 1,000,000 events, 1 GiB of event data). Open checks `COUNT(*)` and `SUM(length(data))`. `AllEvents` reads pages (at most 100 rows or 16 MiB) and deserializes row by row, so memory stays bounded and the limits hold while reading. A row over a limit is never read into memory and throws `DeserializationException`; `LoadSnapshotJson` checks that the text is a JSON object (depth limit 64); the database path is made a full path, so SQLite never reads it as a URI; all SQL is parameterized. A caller must still check the snapshot `version` and its types (T12).
- **Hostile database objects (security review, hardens upstream):** a session file can carry triggers, views, generated columns or changed table definitions that run when this program queries it. Right after open the connection sets `PRAGMA trusted_schema=OFF` and `SQLITE_DBCONFIG_DEFENSIVE` (through `SQLitePCL.raw.sqlite3_db_config`; `Microsoft.Data.Sqlite` has no own API). Before any other query, `SqliteSchema.Verify` compares every `sqlite_master` entry with the entry that the DDL creates in an empty database (name, type, table, SQL text). Any other object (trigger, view, extra table or index, changed definition) throws `StorageSchemaException` and the lock is released. A missing object is allowed; `Ensure` creates it. An existing non-empty file also runs `PRAGMA quick_check(1)`; a failure throws `CorruptDatabaseException`. Tests: `SqliteStorageManagerTests` (untrusted file section).
- **Session lock:** upstream uses `flock` on `<name>.lock` with a `<pid> <hostname>` record. .NET takes a mandatory file-share lock, which blocks readers of the locked file. The port locks `<name>.lock.guard` and keeps the record in `<name>.lock`, so `ReadLockOwner` works while the lock is held. `DeleteDatabase` and `ReadLockOwner` are static methods of `SqliteStorageManager`. Security review: the lock path and the guard path are refused when they are symbolic links (`FileInfo.LinkTarget`, `UnauthorizedAccessException`), and both files are created with mode 0600 on Unix. The record is written by path, not through the guard handle, because the guard handle is locked against readers; the link check and the open are not atomic, so the lock directory must be writable by the user only. An owner check (file uid equals current uid) is not done: .NET has no uid API without P/Invoke.
- **Not ported:** virtiofs detection (the default journal mode is WAL; `SqliteJournalMode.Delete` is the explicit choice for a shared mount); reconnect and retry on `disk I/O error` (needs fault injection to test); `check_same_thread` (one connection with one lock serializes all use); `must_exist` throws `FileNotFoundException` in place of `sqlite3.OperationalError`; `save_snapshot_json` is `SaveSnapshotJson` and also requires a JSON object (upstream: any JSON).
- **Small differences:** `GetLatestSnapshotId` breaks a `created_at` tie by `rowid`. `AllEvents` on the in-memory backend returns a copy. `InMemoryStorageManager` returns null and an empty list for the snapshot queries and throws `StorageNotConfiguredException` for save and load.
**Tests:** the backend contract (`tests/test_event_backend_protocol.py`, round-trip types of `test_event_backend_roundtrip.py`) runs against both backends through the abstract `IEventBackendTests`. `SqliteEventBackendTests`, `SqliteStorageManagerTests` and `SessionLockTests` port `test_sqlite_corruption_resilience.py`, `test_sqlite_specific.py`, `test_sqlite_close_commit.py`, `test_session_resume_tag_collision.py` (SQLite parts) and `tests/storage/test_sqlite_public_options.py`. New tests cover unknown event types, oversized rows, tampered snapshots, schema mismatch and SQL text in tags and ids.
**Skipped tests:** `test_sqlite_reconnect.py` and the virtiofs tests (not ported); registry and `LLMOutput` tests in `test_sqlite_specific.py`; `DecisionRecord`, `Reasoning`, `PythonOutput` value and `_json_safe` tests in `test_event_backend_roundtrip.py` (types or helpers not in the port); every test that needs an `Agent` or `EventManager` (T12); `tests/storage/test_snapshot.py`, `test_serialization.py`, `test_markers.py`, `test_snapshot_vars.py` and `tests/runtime/test_snapshot.py` (T12, T15).

## Storage hardening follow-up (T07b)

**C#:** `SqliteSchema.Verify` compares full `sqlite_master` rows (type, name, table, sql) as a set and refuses any trigger or view outright. Keying by name alone let a trigger that shares a table's name hide behind the table row. `SessionLock.Acquire` refuses a lock directory that is writable by group or others (Unix): .NET has no `O_NOFOLLOW` open, so the symlink check and the open are not atomic, and a directory that only the user can write closes that race.
**Why:** security review of PR #8.
**Tests:** `Open_TriggerNamedLikeATable_IsRefused`, `Acquire_DirectoryWritableByOthers_IsRefused`.

## `PFormat` value printer (agentdoc, T06)

**C#:** `PFormat.Format(value, maxLength, maxString, maxDepth, expandAll, unquoteStrings)`, `PFormat.Format(value, FormatConfig)`, `PFormat.Write(TextWriter, ...)`,
`PFormat.TruncatingFormat(value, maxChars, ...)`, `TruncatingTextWriter` and `FileBackedTruncatingTextWriter`, in `Nooa.Agentdoc`. `FormatConfig.MaxLength/MaxString/MaxDepth` map to the parameters of the same name.
This is what the model reads as values in the `state` block and in REPL output.

| Value | Text |
|-------|------|
| `null`, `true`, `42`, `1.5`, `1.0`, `'x'` | as written. A whole `double`/`float` keeps `.0`. `NaN` and infinity are `double.NaN`, `double.PositiveInfinity`. Invariant culture. |
| string | C# regular literal with C# escapes (`"a\"b\n"`). A string with a line break and no other control character is a verbatim literal `@"..."` that keeps the line breaks (`"` becomes `""`). |
| enum | `Color.Red`, flags `Perm.R \| Perm.W`, unknown `(Perm)8` |
| `Type`, delegate | `typeof(List<int>)`, `<Func<int, int>>` |
| list, array, queue | `[1, 2]` |
| tuple | `(1, "a")` |
| set | `{1, 2}` |
| dictionary | `{"k": v}` |
| record, class, struct | `Person { Name = "Ada", Age = 36 }` (one line, `Name { }` when empty) |
| type with its own `ToString`, and framework objects | the `ToString` text (invariant culture, `DateTime` as ISO 8601). A throwing `ToString` gives `<TypeName>`. |
| cycle | `<cycle>` |

Truncation markers keep the upstream meaning (the marker means the value is not complete):
`string(len=N, [:H]="...", [-T:]="...")`, `List<int>(len=N, [:H]=[...], [-T:]=[...])` (ordered), `HashSet<int>(len=N, items={..., ...})` (unordered),
`Dictionary<string, int>(len=N, items={a: 1, ..., z: 26})`, `Type(text_len=N, [:H]="...", [-T:]="...")` (cut `ToString`), `Name { A = 1, ... }` (members), `{Dictionary<string, int>: 3 items}` / `[List<int>: 3 items]` / `Name { ... }` at the depth limit.
Head is the ceiling half and tail the floor half of the limit. A container whose one-line form is under 120 characters is one line. A longer one has one item per line (4-space indent). `expandAll` forces many lines.

**Why `{"k": v}` for dictionaries:** short, readable for the model, matches the upstream marker (`items={...}`), and cannot be mistaken for a set (a set has no colons). `{ ["k"] = v }` is longer for no gain. An empty set and an empty dictionary are both `{}`, as upstream.
**Why `Name { A = 1 }` for objects:** it is the shape of a C# record `ToString` and of an object initializer, so it reads as C#.
**Safety:** an object shows public fields and auto-properties only (`MemberReader`). It reads the backing field of an auto-property. No property getter runs, also not a virtual one that a derived type overrides with computed code. Members with a leading underscore, `[Hidden]` members and delegates are left out. Only user types are walked by reflection (`ReferencedTypes.IsCustom`): framework objects print `ToString`, so no framework internals are read. Only arrays, tuples, dictionaries, sets and types with a count are enumerated. A lazy `IEnumerable` never is. A reference is tracked while it is written, for `<cycle>`. Nesting is capped at 100 when the caller sets no depth, so a deep structure cannot overflow the stack. A one-line attempt stops when it reaches the width, so the cost stays low for deep structures.
`FileBackedTruncatingTextWriter` creates its file with a random name and mode 0600 (`CreateNew`). A prefix or suffix with a path separator throws. If the file fails, the writer falls back to memory (`FilePath` is null).
**Deviations:**
- `pformat(instance_mode="type")` and `concise` are `Doc()` (T05). They are not parameters of `PFormat`. `console` and `indent_guides` (Rich compatibility) are dropped.
- `pprint()` (`runtime/pprint.py`) is a wrapper that writes `pformat` plus a newline to stdout. `PFormat.Write(TextWriter, ...)` is the core. The REPL `pprint` global comes with the REPL task (T15).
- A limit of 0 or below throws `ArgumentOutOfRangeException` (upstream treats 0 as "no limit" in some paths). Use null for no limit.
- `unquoteStrings` returns the untruncated string as it is. Upstream strips the quotes of its `repr`, which left escapes in the text.
- A type with its own `ToString` prints that text, as upstream honors a custom `__repr__`. This runs user code (it can have side effects or show a `[Hidden]` field). Records keep member printing, because their `ToString` is generated.
- Not ported (Python only): `__instance_values__`, `spec(max_string=...)`, pydantic `exclude`, NamedTuple, `__slots__`, `_ClassRef`/`_InstanceRef`, `sys.stdout` printing.
- Per-field `max_string` override (`test_event_max_string_override`): needs the event types and the context formatter, so it moves to T13 with the "must not truncate" rule.
**Tests:** ported in `PFormatTests` (cycles, head and tail markers, budget parameters, truncating format), `ValueRendererTests` (hidden fields, objects), `LiteralFormatterTests`, `CollectionReaderTests`, `TruncatingTextWriterTests` and `FileBackedTruncatingTextWriterTests`.
Not applicable (Python only): `test_annotated_types`, `test_dataclass_properties`, `test_discover_pep563`, `test_discover_pydantic_forward_refs`, `test_namedtuple_future_annotations`, `test_typeddict_future_annotations`, `test_pandas_adapter`, `test_protocols`, `test_registry`, `test_metadata`, `test_docs` (`spec()`), `test_doc_config`, `test_visibility` (module variables, `hidden` blocks), `test_skill_lifecycle_visibility`, `test_referenced_types_demo`.

## Agent, runtime, event manager, snapshots (T12)

- **`Agent`:** constructor takes `AgentOptions` (D6). Upstream `__init_subclass__` kwargs are the `[AgentOptions]` attribute, instance values are `AgentOptions`. `execution=`, `truncation=` and storage are instance options. Not ported yet: `decision_model` (B03), `render_config`, `context={}` overrides and `event_query` (T13). `Agent` has `[NoSnapshot]`, so an agent never nests in a snapshot. **Security (trust rule, closes the open item of T03/T04):** a project-layer `llm_config.yaml` (or a `NEMO_OO_LLM_CONFIG` file inside the project) is untrusted. `LayerTrust.IsTrusted` is the one trust test, extracted from `Secrets` and used by both. Bundled paths (caller-supplied) are trusted.
1. An untrusted layer cannot replace or remove an alias that a trusted layer defined. The entry is ignored with a warning. This blocks redirect of the prompts of a trusted alias to another host, and loss of its key setting.
2. An untrusted layer never sets `api_key_env`. The field is dropped with a warning that names the alias and the field, never a value. An alias that only untrusted layers define therefore has no key, unless it uses the default OpenAI host with `OPENAI_API_KEY`. This also covers route-prefix defaults: `ParseModel` can give a host (for example `nvidia_nim/` gives `integrate.api.nvidia.com`) when the layer sets no `api_base`. Such an alias gets the placeholder key. Rule 1 also stops an untrusted `model_name` from changing the route of a trusted alias.
3. `api_base` and `endpoint` must not contain user info, a query string or a fragment (`ModelConfig.FromRegistry` rejects them; the message does not echo the URL). `ModelConfig.ToString()` drops user info, query and fragment, because `with` skips validation. The registry logs the host at Debug level, not the URL.
**Why simple:** the rules do not look at which variables exist in the process, so it does not depend on the environment. The cost: a project file cannot tune a trusted alias (for example the temperature). Put such a change in the user file or a `NEMO_OO_LLM_CONFIG` file outside the project. `LayerTrust` has two users (`Secrets`, `ModelRegistry`); the extraction is a move, and one trust test for both lowers the risk that they drift apart.

## ShellTools and BashSession (T20)

**C#:** `Nooa.Tools`: `ShellTools`, `BashSession`, `ShellOptions`, `ShellResult`, `Match`, `FileWrite`, `StaleMatchException`, `SearchCommand`, `ShellLifecycle`, `BackgroundServiceScope`, `StreamEvent`, `StreamDone`. POSIX only.
- **Plain classes:** upstream `ShellTools` is a `Skill`. The skill and REPL exposure come with T17/T22 (note in `work/t17-codeact.md`). `ShellTools` has `RunAsync`, `RunStreamAsync`, `ReadAsync`, `ReplaceAsync` (match form, path form, and a rejecting overload for `(match, old, new)` so a mixed call gets the upstream instruction), `WriteFileAsync`. `Match.Slice(start, end)` replaces `match[start:end]`. `StaleMatchError` is `StaleMatchException : ShellToolException : NooaException`. `ShellResult` is a class with `Stdout`, `Stderr`, `ReturnCode`, `Success`, `TimedOut`, `Matches`; it is not a `str` subclass, and `ToString()` keeps the `BashOutput(...)` form. `is_pure_search_command` is `SearchCommand.IsPure`.
- **Security (opt-in):** there is no default instance. The constructor needs `ShellOptions` (`Cwd` is required). Windows throws `PlatformNotSupportedException`. The tool runs commands and file operations as the host user, with no sandbox and no path containment (upstream is the same; the shell can reach any path anyway).
- **Security (environment):** upstream passes `os.environ`. The port passes only PATH, HOME, LANG, USER, SHELL, TMPDIR (when set), `TERM=dumb`, `PS1=""` and `ShellOptions.ExtraEnvironment`. No API key and no `BASH_ENV` reaches the shell. The ripgrep helper runs with a clean environment (only PATH), so `RIPGREP_CONFIG_PATH` has no effect.
- **Security (framing, no fd 3):** upstream sends the exit code, directory and job PIDs on fd 3. `Process` cannot pass an extra fd, so the frame goes on stdout and a marker goes on stderr. Both hold `__NOOA_<32 hex>__`, new for each command (plan: random nonce). Text that a command prints cannot forge a frame. The sentinel reaches bash only after the command ends. A command that deliberately reads the shell's stdin pipe could learn it; the shell is not a sandbox. A command that redirects the shell's own stdout or stderr (`exec >file`) hides the frame: it times out and the session restarts (upstream's fd 3 survived this). One `printf` writes the frame, so output of a background job cannot split it. The directory is escaped (`%`, line break) inside the frame.
- **Command transport:** upstream base64-encodes the command and runs `eval "$(base64 -d ...)"`. The port writes the command to a private scratch directory (mode 0700, `CreateTempSubdirectory`) and sources it with stdin closed. Reason: no dependence on `base64`, no `ARG_MAX`, the same protection against an unparseable command (`. file </dev/null`). The files are deleted after each command and on close. `stdin=` uses a scratch file instead of `mktemp` and `base64`: `{ command\n} < file`. Bash reads only protocol lines from the pipe.
- **Process group:** .NET cannot start a process in a new session. Bash starts under `setsid` (`/usr/bin/setsid`), or under `perl -MPOSIX -e 'setsid(); exec @ARGV'` when `setsid` is missing (macOS). Neither present: `ShellToolException`. The shell PID is then the group id. Close and dispose send SIGTERM to the group, wait 3 seconds, then SIGKILL (no group signal when bash already exited: the group id could be reused). Signals use `libc` `kill` through `DllImport` (`LibraryImport` needs `AllowUnsafeBlocks` for the whole project).
- **Timeout and recovery:** a timeout is a `CancellationToken` linked to the caller token. It ports the upstream recovery: snapshot descendants of bash (Linux `/proc` with start time; macOS `libproc` `proc_listchildpids`, which starts no process; `ps` as fallback), skip earlier background jobs and their subtrees, SIGTERM them (SIGINT to bash when none), wait 5 seconds for the frame, SIGKILL the captured targets, wait 2 more seconds, then reset the session. Exit code 124 and `TimedOut = true`. A cancelled caller token ends the command the same way and then throws `OperationCanceledException`. After a recovered timeout the directory is updated from the frame (upstream ignored it).
- **Output bound:** each stream goes through `TruncatingTextWriter(30000)` as it arrives (head and tail), so memory stays bounded for a very large output. Upstream collected everything and then truncated. Output that arrives between commands (a background job) is dropped; upstream added it to the next command.
- **Readers:** one persistent reader task per stream and one collector per stream replace upstream's per-command cancellation and the 50 ms drain. Both markers must arrive, so output is complete without a timer.
- **Not ported:** event-loop change handling (`_ensure_lock_on_current_loop`, `_reset_for_loop_change`; asyncio-specific; `SemaphoreSlim` has no loop). `harness_metrics` (T19). `_diagnose_death` (`/proc` diagnostics): the session logs the exit code through `ILogger` and never logs commands or output. `_results.py` types `RunResult`, `ViewResult`, `EditResult`, `WriteResult`, `SearchResult`, `LsResult`: nothing in upstream uses them outside their own test. `StreamEvent` and `StreamDone` are ported with `RunStreamAsync`. `ShellTools.__repr__`. The REPL hint line that `run()` printed after a search with matches.
- **`keep_background_on_close`:** `ShellOptions.KeepBackgroundOnClose`. Close ends bash only (stdin EOF, then SIGKILL after 3 seconds). Upstream starts a detached Python drainer that reads the pipes after the owner exits. The port keeps the reader tasks running, so a kept job does not get SIGPIPE while the host process lives. After the host exits the pipes close. A job that must outlive the host redirects its output. `ShellLifecycle.PreserveBackgroundServices()` (an `AsyncLocal` scope, `await using`) and `BackgroundServiceScope.Adopt` port `shell_lifecycle.py`. The method must not be `async`, because an async method drops the scope when it returns. The scope keeps strong references to its sessions. There is no destructor kill (upstream `__del__`): dispose the session. A session that nobody disposes leaves bash until stdin closes at finalization.
- **Search anchors:** `rg --json` runs as a direct process with the shell directory as working directory and a 30 second limit and an 8 MiB output cap. Upstream runs it inside the session with a harness-specific `PATH` prefix (`/opt/harbor/...`), which is dropped. Pattern and paths are arguments after `--` (never shell text). Only a known flag set is accepted (`-i`, `-F`, `-r`, `-R`, `-n`, `-H`, `--ignore-case`, `--fixed-strings`), so `--pre` and similar flags cannot reach ripgrep. A missing `rg` means `Matches` is `null`. Regexes have a 1 second timeout (the command is model-written text); a timeout means no anchors. A path that is not valid UTF-8 means no anchors (upstream raises `KeyError`).
- **File operations:** read with strict UTF-8, universal newlines (CRLF and lone CR become LF, as Python text mode) and no BOM stripping; write UTF-8 without BOM. Lines split at `\n` only: Python `splitlines` also splits at `\v`, `\f`, `\x1c`-`\x1e`, `\x85`, `\u2028`, `\u2029`, so its line numbers could differ from grep and ripgrep. The CRLF-to-LF rewrite on edit is upstream behaviour and the upstream test pins it (`test_valid_producers_and_line_endings`).
- **Stale diff:** `difflib.unified_diff` is replaced by a small LCS diff (`UnifiedDiff`) with the same hunk format and three lines of context. The input is capped at 16 KiB and 400 lines, so the quadratic table is small. `difflib` may pick another diff for ambiguous inputs; the tests only fix simple cases.

- **Package:** `Microsoft.CodeAnalysis.CSharp.Scripting` 5.3.0 (same as `Microsoft.CodeAnalysis.CSharp`), published 2026-03-10, license MIT (nuspec `licenseExpression`).
- **Types:** `IExecutionEngine` and `RoslynExecutionEngine` (`Nooa.Runtime`). `ReplGlobals` (members `Console`, `Out`, `Print`, `PPrint`, `Doc`, `ReturnResult`, `Cancellation`) and `ReplGlobals<TAgent>` (adds `self`, typed as the agent). `CellResult` replaces `ExecutionResult`. `ReplOptions` holds timeout, grace, capture budgets, extra references and imports, and the validator. `ICellValidator` is the seam for T16: it runs before compile and throws `RestrictedCodeException`.

Partial output is kept for both. A cell that ignores the token cannot be stopped in the process. After `AbandonGrace` (default 5 s) the engine returns an error and refuses every later cell, because the old cell still uses the state (B01 is the real fix).
- **Guardrails, not a boundary (D12):** references are `System.Runtime`, `System.Collections`, `System.Linq`, `System.Text.Json`, the Nooa assembly, the assemblies of the globals type and `ReplOptions.References`. `#r` and `#load` are refused with a line number. Unsafe code is off. The list hides whole assemblies (`System.Console`, `System.Diagnostics.Process`) but the facade `System.Runtime` forwards to the core library, so `System.IO.File`, `System.Reflection` and `Environment` still compile. T16 must deny namespaces and types.
- **Errors:** `ErrorFormatting.FormatForLlm` (`Nooa.Errors`) ports the intent of `format_error_for_llm`. Compile errors show `Cell In[N], line L`, the source line, a marker and `error CSxxxx: text` (ten at most). Framework frames are removed. The text is cut to `CaptureConfig.MaxError` and `Tail`. A formatter failure falls back to `Type: message`. ## Code validator (T16)

- **Types:** `CellCodeValidator` (`Nooa.Runtime`, implements `ICellValidator`), `CellValidatorOptions`, `RestrictedApiGroup`. Internal: `CellValidationWalker` (Roslyn syntax walker plus semantic model), `RestrictedApiCatalog` (deny lists), `RestrictedApiRule`, `CellIssue`. `RoslynExecutionEngine.FrameworkAssemblies` and `DefaultImports` are now internal so that the validator binds names with the same references and imports.
- **Not a boundary (D12):** the XML docs say so. The validator is defence in depth. The cells run in the host process, and a static check cannot cover every path to an API (B01 is the real fix).
- **Semantic, not textual:** the validator binds every simple name with the semantic model of a script compilation. Aliases, `global::`, `using static` and full names resolve to the same symbol, so they cannot bypass a rule. Constructors are checked on `new` expressions. A rule covers a namespace (prefix), a type, or one member.
- **Cell chain:** the validator keeps the compilation of each accepted cell as the previous script compilation, as the engine does. A variable of an earlier cell has its real type, so `t.Result` is found when `t` came from an earlier cell. A rejected cell is not chained, and neither is a cell that does not compile (Roslyn refuses a previous submission with errors; found by the CodeAct tests in T17). The validator is stateful: one validator for one engine. Cost: one script compilation per cell (a few ms to tens of ms).
- **Names that cannot be bound:** the variables that `DeclareArgumentsAsync` creates are not visible to the validator. For an unbound name the validator refuses the simple names of restricted types (`File`, `Process`, `GetType`, ...) by text. This is fail-closed and may refuse a user name that is unbound and equal to such a type name.
- **Mapping of upstream lists:** `DEFAULT_BLOCKED_MODULES` (subprocess, socket, http, smtp, ...) to `System.Diagnostics.Process`, `System.Net`, `System.Data`, `Microsoft.Data` (groups Process, Network). `RESTRICTED_MODULES` (os, shutil, pathlib, tempfile, sys, ctypes) to `System.IO.File/Directory/FileInfo/DirectoryInfo/FileStream/DriveInfo/FileSystemWatcher`, memory-mapped files, `ZipFile`, `StreamReader/StreamWriter` with a path, `Environment` (only `NewLine` and `ProcessorCount` pass), `System.Runtime.InteropServices`, `Unsafe`. `FORBIDDEN_BUILTINS` (`exec`, `eval`, `compile`, `__import__`, `globals`, `vars`) to `System.Reflection`, `Type`, `Activator`, `AppDomain`, `Assembly` loading, `Microsoft.CodeAnalysis` (Roslyn scripting is `eval`), `Expression.Compile`, `Delegate.DynamicInvoke`, `object.GetType()`, `dynamic`. `exit`/`quit`/`sys.exit`/`os._exit` to `Environment.Exit`, `Environment.FailFast`, `Debugger`. `input`/`breakpoint` to `System.Console` (also not referenced) and `Debugger`. `DEFAULT_BLOCKED_CALLS` (`time.sleep`, `Thread.join`, `Lock.acquire`, `Event.wait`, `asyncio.run`) to `Thread.Sleep/Join`, `Task.Wait/WaitAll/WaitAny`, `Task.Result`, `GetAwaiter().GetResult()`, `WaitHandle.Wait*`, `SemaphoreSlim.Wait`, `Monitor.Enter/Wait`. Syntax: `unsafe`, `fixed`, pointers, `extern`, `dynamic`.
- **Opt-in:** `CellValidatorOptions.Allow` (flags). Blocking calls, unawaited tasks, type declarations, recursion and return-type shadowing cannot be allowed.
- **Await:** CS4014 is raised to an error in the validator compilation and reported with the other issues. `_ = Task.Delay(1);` and `var t = Task.Delay(1);` pass. `#pragma warning disable` is refused so that the model cannot hide CS4014. Upstream E301 checked only `self.method()` and allowed a call inside a list comprehension. CS4014 covers every task-returning call, and a task that is collected for `Task.WhenAll` must be assigned to a variable first.
- **Type declarations:** class, struct, interface, enum, record and delegate declarations are refused (upstream refused only a class that shadows the return type, E501). Local functions, tuples and anonymous types remain.
- **Recursion:** `CellValidatorOptions.ForbiddenSelfCalls` names the methods that `self.X(...)` must not call (upstream E004). **Return-type shadow:** `CellValidatorOptions.ReturnType` gives the names (the type and its non-`System` type arguments). Variables, pattern variables, methods, local functions and `using` aliases with such a name are refused (upstream E501 checked top-level class, def and assignment). T17 fills both options from the running method.
- **Messages:** one text for all issues: `The code breaks N rules`, then for each issue `line L`, the source line, a marker and a sentence with a hint (as upstream `_format_error`). `RestrictedCodeException.LineNumber` is the first line. Syntax errors are left to the compiler.
- **Not ported:** E101/E102/E104 (dunder access, `__builtins__`, `setattr` of dunders), E001 for `set_restricted_imports`, E003 wildcard import (no C# analog), E005 `raise SystemExit` (the C# analog is `Environment.Exit`), E303 infinite loop (not in the checklist), E401/E402 class attribute assignment (C# types are not assignable), `strip_redundant_imports` (C# redundant `using` is harmless), `RestrictionsConfig` global override (`set_restricted_imports`), and `async_safety.py` runtime patches of `concurrent.futures` (Python only). The access to `ReplGlobals.__args`, `RoslynExecutionEngine`, `ReplOptions`, `ICellValidator` and `CellCodeValidator` is refused so that a cell cannot loosen its own guardrails (analog of `get/set_restricted_imports`).
- **Tests:** `CellCodeValidatorTests` ports the intent of `test_code_validator.py` (security, blocking, REPL policy, shadow, integration), `test_blocking_call_validator.py` and `test_restricted_imports.py`. Python-only cases are skipped (`exec`/`eval`, dunders, `asyncio.run`, import rewriting, `RestrictionsConfig`).

## Tracing (`tracing/`, T19)

**C#:** `Nooa.Tracing`. Spans come from `ActivitySource("Nooa")` (`NooaTracing.Source`). `NooaTracing.Enable(...)` installs `OpenInferenceHooks` and an `ActivityListener`. The listener scrubs each finished span and passes it to `ISpanExporter`s. `Shutdown` undoes it. A host that uses the OpenTelemetry SDK can skip this and call `AddSource("Nooa")`.
- **No OpenTelemetry package (deviation from the plan table).** The plan listed `OpenTelemetry` and `OpenTelemetry.Exporter.OpenTelemetryProtocol`. They are not added: `System.Diagnostics` has everything the hooks need, and upstream sends OTLP as JSON anyway. `OtlpJson` writes the OTLP `TracesData` JSON. `JsonlSpanExporter` (`exporters.jsonl`, `OtlpJsonFileExporter`) and `OtlpHttpSpanExporter` (`local_otlp`, `OtlpJsonHttpExporter`) use it. No package, no license or age check needed.
- **Spans.** AGENT `method.<Name>` per traced agent call, CHAIN `generation` per generation session (upstream names and attributes: `agent.*`, `generation.*`, `input.value` as JSON `{"args":[],"kwargs":{...}}`, `output.value`, `result.type`, `nooa.viewer.plugin`, `session.id`, errors with `error.*` and `exception.*`). The parent of a call is the span of `parent_call_id`, so a nested call hangs under the outer agent span, as upstream. The LLM span comes from `TracingLlmClient` (or `TracingLlmClientResolver`) with the OpenInference `llm.*` attributes, in place of the LiteLLM instrumentor. `llm.input_messages` keep the first 50 and the last 50 messages (count of omitted ones in `nooa.llm.input_messages.omitted`). Reasoning text and opaque provider state are not recorded.
- **Not ported (scope).** Code-execution, tool-execution, method-invocation and `context_snapshot` spans: `IInstrumentationHooks` has no such methods yet. T17 adds the hooks with their callers (note in `work/t17-codeact.md`). Also not ported: journal exporters and `_litellm_*`, Langfuse, `probe_otlp_endpoint` and `resolve_otlp_endpoint` (no viewer), `emit_status`, `register_hooks_in_current_context` (hooks are process-wide, not per context), `_metadata` git capture (it spawns `git`; the resource has `service.name`, `nooa.version`, `dotnet.version`, `hostname`, `experiment`), `SessionSpanProcessor` (the hooks stamp `session.id` at span start), the span-id RNG isolation (the .NET id generator does not use a user-seedable `Random`), `Enable` composition with other hooks (it throws when other hooks are installed).
- **Security: no secrets in spans.** `SpanAttributes.Set` is the only way the hooks write a value. It scrubs (`SecretScrubber`, port of `_secret_scrubber.py`), then bounds the size (50 000 characters, errors 5 000, 1 M characters scanned). The listener scrubs again at span end for tags that other code adds. Deviation from upstream: the value of every credential-shaped environment variable (`SecretEnvDenylist.IsCredentialShaped`, 8 characters or more) is redacted wherever it appears. All regexes are `NonBacktracking` with a 2 s timeout, and a timeout redacts the whole string (fail closed). JSON text nested deeper than 64 levels is redacted whole (upstream does the same on `RecursionError`). The HTTP exporter never puts a token in a span. `NOOA_VIEWER_AUTH_TOKEN` goes only over https or to a loopback host, redirects are off, and the endpoint must be an http(s) URL without user info.
- **`[NoTrace]`.** The runtime already skips the agent-call hook. `OpenInferenceHooks` also skips the generation span for such a method (by name, any overload, or the class), and an async-local flag (`TraceSuppression`) stops `TracingLlmClient` from recording the LLM span inside it. The arguments and the result of such a method appear in no span. Upstream still emits the generation span.
- **Security: files.** `JsonlSpanExporter` refuses a directory or a file that is a symbolic link (not atomic with the open: the directory must not be writable by an attacker), creates the directory with mode 0700 and the files with mode 0600 on Unix, and accepts a session id as a file name only when it matches `[A-Za-z0-9_-][A-Za-z0-9._-]{0,127}` (otherwise the spans go to the timestamp file). The directory comes from code or from `TRACE_DIR` (process environment). No config layer sets a trace path, so `LayerTrust` does not apply; a future config key must use it.
- **Concurrency.** Hooks keep open spans in a `ConcurrentDictionary` by call id; the current span flows through `Activity.Current` (an `AsyncLocal`). `OtlpHttpSpanExporter` uses a bounded channel (8192) and one worker; a full queue or a failed request drops and counts the spans and logs once per batch. `Channel` `DropWrite` makes `TryWrite` return true, so the exporter uses `Wait` mode to detect a full queue.
- **Tests ported (intent):** `test_secret_scrubber.py` (all patterns, JSON, nesting, provider state), `test_openinference_conformance.py` (names, kinds), `test_tracing_integration.py`, `test_concurrent_spans.py` and `test_context_isolation.py` (parent-child, separate traces), `test_safe_serialize.py`, `test_exception_stacktrace.py`, `test_exporters.py`, `test_http_exporter_drops.py`, `test_idempotent_tracing.py`, `test_exporter_isolation.py`. Quickstart 06 is `Quickstart06TracingTests` (offline, `MathAgent` with a fake model, JSONL file read back).
- **Tests skipped:** journal, litellm, viewer, harbor, probe, metadata, `ScrubStats` (no global counters; the count is a span attribute), span-id RNG, subprocess hooks, reasoning OTLP and wire-strip tests.
- **Security review fixes (T19).** (1) Values are scrubbed in full before any cap: `TracingLlmClient` no longer caps, `SpanAttributes.RecordError` scrubs the message and the stack trace before it caps, and the 1 M-character pre-cap drops a 256-character margin at each cut so a secret is never left half-cut. (2) `SecretScrubber` scrubs JSON object keys. (3) The environment-value pass runs before the regex pass, so a regex replacement cannot hide an environment value. (4) The OpenAI pattern is `sk-(?:proj-|svcacct-|admin-)?[A-Za-z0-9_-]{20,}` (the Anthropic pattern stays first). (5) `OtlpJson` scrubs every string that it writes (attribute keys and values of any type, span name, status message, event names and event attributes, resource attributes), so JSONL and HTTP export have no path around the scrubber; `NooaTracing` still scrubs tags at span end as a second layer.
- **Hardening (T19b).** Deviations from upstream: a JSON string value with no match alone is checked again as `key=value` text, so the key-anchored patterns apply inside JSON. Sensitive key names also match without separators (`apiKey`, `accesstoken`), as a suffix. `ScrubValue` redacts the whole value on an unexpected failure. The HTTP exporter catches every exception for each batch and counts the spans as dropped, so the worker stays alive.

## CodeAct strategy (T17)

- **Tools and names:** `execute_csharp(code)` and `return_result(value)`. A cell can also call `ReturnResult(value)` or `return value;`. All strategy text, error hints and the unknown-tool feedback are rewritten for C#. Block order is `system_prompt`, `strategy_prompt`, `execution_context`, `self`; `sandbox` is not ported.
- **Default strategy:** CodeAct, as upstream (see T14 note "Default strategy"). `Agent.ResolveStrategy` creates one lazy instance.
- **Execution context block:** the usings of the cell scope (defaults plus the namespaces of the agent, return and argument types), the typed task parameters and the always-available names. Upstream built it from the agent module. The engine, the validator and the block use `CodeActScope`, so the prompt shows what compiles. The agent type must be public (clear `GenerationException` otherwise).
- **Per call state:** one `RoslynExecutionEngine` and one `CellCodeValidator` per call (the validator is stateful). Cells never see state of an earlier call. Upstream passed `session_locals` between nested calls; that is not ported.
- **`return_result`:** the tool schema is `{"result": <return type>}` (a type with no JSON schema gets an open schema and a description that sends the model to `ReturnResult(variable)`). Accepted shapes: field arguments without `result`, a cell variable name, a JSON object or array string, a value of another type converted through System.Text.Json (`int` to `double`, dictionary to record), a string wrapped in extra quotes. A string is never evaluated as code: the constructor-string evaluator is not ported. `null` is accepted for reference and nullable types only. Missing members are caught only for `required` members (T14 note). `return_result` as a tool call or a cell call both run the postconditions; an `InvariantException` goes back as feedback and counts as an error.
- **Explicit return:** `ReturnResult(x)` and a top-level `return x;` both end the task with strict validation (upstream auto-completed a bare `return` silently and kept looping on a type mismatch). The engine does not tell the two apart.
- **Empty cell:** runs through the engine so the cell number stays unique (`In[n]` and `Out[n]`), then reports "empty code provided".
- **Prefill:** `InspectInputsPrefill` prints each argument with the declared type (not the value type, no `GetType()`), `PPrint` with the `PrefillFormat` limits, and `Doc(typeof(T), concise: true)` for a complex return type. A scalar or a collection return type is "simple" (upstream: str, int, list, dict); an enum is complex. `pre_ellipsis_code` is not ported (T14). A prefill failure is recorded and the run goes on; a prefill that abandons the engine ends the call.
- **Loop guard:** ported with the same thresholds and templates. The code fingerprint is the Roslyn syntax tree without comments (upstream `ast.dump`). The outcome of a call comes from the handler (upstream re-read the events). The stop message uses a fixed tool name (`execute_csharp`, `return_result`, else "unknown tool") so no model text is in the exception.
- **No model text in exceptions:** the text-only abort and the validation-exhausted exceptions drop the "Last text" and "Last error" parts of upstream. The text stays in the `TextOnlyReply` and `Error` events, which the renderer escapes (`</` is neutralized). A tool result is not wrapped by the block formatter, so the strategy neutralizes closing tags in the feedback it puts there.
- **Abandoned cell:** the call ends with `GenerationException` after the cell output is recorded. Cancel: the output is recorded as `Cancelled`, then `OperationCanceledException`.
- **Cell values in events:** `CellOutput.Value` is JSON (D11). A collection becomes bounded `PFormat` text and a lazy sequence is read only up to the format limit (an endless sequence must not hang the run). A `PFormat` call on an endless sequence is not bounded; only the CodeAct path guards it.
- **Not ported:** `translate_tool_calls`, the `on_text_only` handler type (the default retry is fixed), `max_tool_calls`, sampling parameters per call (no per-call settings in `IRuntimeServices.GenerateAsync`), `tool_choice`, the `sandbox` backend (B01), `BlockSyntaxError` handling (no expression blocks), harness metrics, media in prefill, `before_tool_execution` hook for `return_result`, the `_iter_agent_attrs` class discovery (C# namespaces replace it).
- **Tracing (T19):** `IInstrumentationHooks.BeforeCodeExecution` / `AfterCodeExecution`, called for each cell (prefill too). `OpenInferenceHooks` emits a TOOL span `code_execution` under the generation span; input `{"code"}` (10 000 characters), output `{stdout, stderr, returned_value}`, all through `SpanAttributes.Set`. A `[NoTrace]` generation suppresses it.
- **Tests:** `test_codeact_strategy.py` and the CodeAct cases of `test_strategy_validators.py` are ported in intent as `CodeActRunTests` (end to end through generated agents and `FakeLlmClient`), `ReturnResultValidatorTests`, `CodeActErrorsTests`, `CodeActPromptsTests`, `LoopGuardTests`, `InspectInputsPrefillTests`. Quickstart 03 and 04 are `CodeActAcceptanceTests`. Python-only cases (AST constructor evaluator, `pformat` kwargs, sandbox, `session_locals`, harness metrics) are skipped.

## ContextApi, EventsApi and expression blocks (T18)

**C#:** `Nooa.Runtime.ContextApi` and `EventsApi` (public, doc comments are the model prompts), internal `ContextExpressions`, `Context.Expr(text, prefix)`. `Agent.Context` and `Agent.Events` are `[Hidden]`. Opt-in (upstream `spec(self, "context", hidden=False)`): the subclass declares `public new ContextApi Context => base.Context;`. A cell sees `self.Context` and `self.Events` either way, because `[Hidden]` only changes the docs and the state block.
- **`Context.Expr`:** the text is one C# expression, not a statement (`ParseExpression`, no semicolon, 4096 characters at most). `ContextManager.Set` (also `AgentOptions.Context`, `ScopedContext` and strategy overrides through `ContextBuilder`) binds it through `ContextExpressions` and stores a provider, so D5 still holds: blocks hold delegates. A `ContextManager` with no agent refuses an expression (`InvalidOperationException`). `Context.Provider` stays null for an expression block.
- **Evaluation:** each evaluation runs the text as a cell in a new `RoslynExecutionEngine` with `ReplGlobals<TAgent>` (`self`), a new `CellCodeValidator` (no restricted API group allowed, `[Agentic]` method names in `ForbiddenSelfCalls`), the namespaces of the agent type plus `Nooa.Agentdoc`, and a 5 second limit. `Bind` also validates at set time, so a bad expression fails when the model sets it and nothing is stored. A failed evaluation throws `ValidationException` with the cell error, and the builder shows `ValidationException: ...` in the block (as for any failing provider). The agent type must be public. Measured: about 45 ms per evaluation on this Mac, after warm-up. A new engine each time avoids the validator chain growth (`CellCodeValidator` keeps accepted cells) and variable leaks between turns; the memory growth of REPL cells (T15 note) applies per evaluation. Measure before you cache an engine.
- **Security:** an expression is code and gets the model-cell checks. It is never read from a snapshot or a config: `AgentSnapshot` does not save a block with a provider (existing rule, now tested for expressions), and no loader turns stored text into an expression. So the "declared by the agent class" rule holds by construction: only host code and model code in the process can set one. The result goes through the normal block text path (XML escaping, `ContextBlockFormat` bounds), tested with closing tags in the value. A snapshot still cannot change a protected block (T14 rule).
- **`ContextApi`:** indexer (get/set, string, `Context`, null hides), `Contains`, `Count`, `Keys`, `GetOrDefault`, `Remove`, `Pop`, `Set(key, value, expr, prefix)`, `SetDynamic(key, expression)`, `Disable`, `Enable`, `Disabled`, `IsEnabled`, `AllKeys`. Keys are 128 characters at most. Protected keys are readable by name and hidden from `Contains`, `Keys` and `Count`, as upstream. Not ported: `set_static` (use `Context.Of(value, prefix: true)` or `Set(..., prefix: true)`), `set_dynamic(value=)` (use the indexer; the host has `ContextManager.SetDynamic`), the `DeprecationWarning`s (nothing is marked obsolete: upstream deprecates them only in favour of the indexer).
- **`EventsApi`:** `Query`, `Get` (key or list), indexer (key or list), `Contains`, `Collapse` (string tags; int tags must identify existing events), `Keys`. Input from the model is bounded: at most 200 results (default and cap, the most recent win), 128 characters for type, call id, status and tags, 1000 for text, 256 for a regex, 20 000 for a summary text, 200 keys per call. A limit below 1 throws. Upstream `limit=None` returned all events.
- **Regex (security):** `EventManager.Filter` now uses `RegexOptions.NonBacktracking` and treats a timeout as no match. A pattern with a lookaround or backreference throws `NotSupportedException` (`EventsApi` rethrows `ArgumentException`). Upstream used backtracking `re` with no limit. `EventQuery` is unchanged (T13 test keeps its timeout exception).
- **Prompt text:** `ContextWindowStats.Format` and the `Summary` doc now say `self.Events...` and `Doc(self.Context)`, the names that a cell can use (`this` is not valid in a cell).
- **Other fix:** `NooaJson.Options` sets `TypeInfoResolver` at creation. Without it `ToolSchema.FromType` failed with "options are read-only" whenever a test serialized a value first; adding test classes changed the order and exposed it.
- **Security review fixes (T18):** (1) `CellCodeValidator` now checks `ForbiddenSelfCalls` by symbol: any method of the agent type or a base type with a listed name is refused whatever the receiver (alias variable, lambda parameter, `Func` conversion, method group, `new Func<>(...)`). The old `self.X(...)` text check stays as a fallback. Expressions list every `[Agentic]` method name. `AgentContext.EvaluatingExpression` is set while an expression runs, and `ActorRuntime.InvokeAsync` throws `NooaRuntimeException` for an agentic call that starts in that scope (also covers code the symbol check cannot see). (2) An evaluation that reaches the time limit or is abandoned marks its expression text as failed: it is not evaluated again, also after the block is set again. An agent keeps at most 3 abandoned evaluations (each holds a thread that cannot be stopped in process, B01): after that no expression is evaluated. (3) The validator refuses any `[Hidden]` member that `Nooa.Agent` itself declares (`Context`, `Events`, `ContextManager`, `EventManager`, `Storage`, `Llm`, ...), for every cell and expression. A subclass opts in with a member of the same name and no `[Hidden]` (`public new ContextApi Context => base.Context;`), which binds first. User-declared `[Hidden]` members are not refused (they hide from docs only). Tests: `CellCodeValidatorTests`, `ContextExpressionsTests`.
- **Tests:** `ContextApiTests`, `EventsApiTests`, `ContextExpressionsTests` (new, from `test_context_api.py`, `test_events_api.py` and the expression cases of `test_context_manager.py`), `ContextAcceptanceTests` (quickstart 05, 07 and 08 offline with `FakeLlmClient`), additions to `ContextTests`, `EventManagerTests`, `ContextWindowStatsTests`, `NooaJsonTests`. Skipped: Python `expr` tests that use Python syntax (`BlockSyntaxError`, f-strings, `eval` namespaces), the `DeprecationWarning` tests, `_MISSING` sentinel tests.
- **Known flake (not from T18):** `RoslynExecutionEngineTests` timeout tests fail now and then under a loaded full run (also on `origin/main`).
